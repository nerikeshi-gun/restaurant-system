# 顧客画面・誤操作復旧テスト

顧客が操作を間違えても、注文内容を壊さず同じ画面からやり直せることを確認する。件数ではなく、各ケースの「失敗後の復旧」と「データ整合性」までを合格条件にする。

| ID | 開始状態 | 誤操作・例外 | 合格条件 | 自動化 |
|---|---|---|---|---|
| C-01 | 言語選択前 | 言語・注文方法の画面を飛ばして音声URLを開く | 顧客用音声画面が開き、最初からへ戻れる | 済 |
| C-02 | 言語選択前 | 言語・注文方法の画面を飛ばしてメニューURLを開く | 顧客用メニュー画面が開き、最初からへ戻れる | 済 |
| C-03 | 注文方法選択 | 不正な言語・モードをURLへ指定 | 日本語の注文方法選択へ安全に戻す | 済 |
| C-04 | 注文方法選択 | ブラウザの戻る | スタッフ画面へ移動せず、現在の顧客画面を操作できる | 実ブラウザ済 |
| C-05 | 音声画面 | ブラウザの戻る | スタッフ画面へ移動せず、音声画面を再操作できる | 実ブラウザ済 |
| C-06 | 音声画面 | 入力せず「話した内容を確認」 | エラーを表示し、ボタンが再操作できる | 実ブラウザ済 |
| C-07 | 注文候補あり | 再読込・言語変更・注文方法変更 | 同じ注文ID・数量・未確定状態を復元する | 済 |
| C-08 | 商品選択 | 数量0・100・負数 | 登録せず、正しい数量で再試行できる | 済（3境界） |
| C-09 | 商品追加中 | 追加ボタンを二重押し | 1件だけ登録し、二重登録しない | 済 |
| C-10 | 古い画面 | 別操作後に古い版で追加 | 競合を返し、最新再読込後の再試行は成功する | 済 |
| C-11 | 注文候補なし | 注文確定を先に押す | 確定せず、商品追加後は正常に確定できる | 済 |
| C-12 | 確定処理中 | 確定を二重押し | 厨房送信・明細・確定回数を重複させない | 済 |
| C-13 | 未確定商品あり | 間違えて取消後、同じ商品を選び直す | 取消履歴を保持し、新しい明細だけ確定する | 済 |
| C-14 | 確定・調理前 | 取消依頼→厨房が承認後、同じ商品を再注文 | 承認までは取消扱いにせず金額を保持し、承認後に金額を0へ戻して再注文を受け付ける | 済 |
| C-15 | 調理中 | 取消を押す | 取消依頼として厨房へ送り、厨房が断ると確定・調理中の状態へ戻る | 済 |
| C-15b | 提供済み | 取消を押す | 取消を拒否し、確定・提供済みの状態を保持する | 済 |
| C-16 | 他テーブルに明細あり | 別テーブルの明細を変更 | 拒否し、自分の明細はその後も変更できる | 済 |
| C-17 | メニュー表示後 | 商品が売り切れになる | 登録を拒否し、再読込後に別商品を選べる | 済 |
| C-18 | 会計依頼前 | 会計を二重押し | 依頼を1件だけ作り、注文内容は再読込できる | 済 |
| C-19 | 問い合わせ | 空白だけで送信後、内容を入れて再送 | 空送信を拒否し、正しい再送は成功する | 済 |
| C-20 | 利用終了後 | 古い画面から注文・問い合わせ | 画面/APIとも受付を拒否し、新規データを作らない | 済 |

## 端末依存で別途行うケース

- Androidの物理戻る・戻るジェスチャー
- マイク許可の拒否、許可後の再試行、録音中の画面離脱
- Wi-Fi切断中の追加・確定と、復旧後の自動再接続
- 連打、長押し、画面回転を組み合わせた操作
- 複数タブレットから同じテーブルを同時操作する競合
