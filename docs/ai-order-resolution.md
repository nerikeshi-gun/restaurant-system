# AI注文候補解析仕様

## 原則

- RAG、ベクトル検索、類似度検索による事前絞込みは行わない。
- 注文時刻に有効な店舗メニュー全件をJSON化し、認識原文と一緒にAIアダプターへ渡す。
- AIは商品候補、数量候補、操作候補、オプション候補だけを返す。
- 候補が一件でも人が画面上のボタンを押して選択する。
- 候補選択後は共有注文の未確定明細へ追加し、注文全体のタッチ確定後に厨房へ送る。
- 価格、売り切れ、数量変更、取消、会計、同期、厨房状態、在庫、POS処理をAIに任せない。

## 店舗メニュー

`stores`が店舗、`menu_versions`が店舗別の有効期間、`menu_version_items`が版ごとの商品スナップショットを表す。既存の`menu_items`は通常の注文処理で参照する現行商品マスターとして残す。

注文解析では`store_id`と現在時刻から次を満たす最新の`menu_versions`を一件取得する。

```text
valid_from <= 注文時刻 < valid_to
```

`valid_to`が空の場合は無期限とする。CSVで新バージョンを取り込むと、それまでの有効版の終了日時を新バージョンの開始日時へ設定する。

## API境界

```text
POST /api/ai/resolve-order
```

クライアント入力は店舗ID、音声認識原文、入力言語だけである。メニュー全件の取得、AI用JSON生成、APIキー、モデル接続、出力検証は中央サーバー内で行う。

AI出力の外部`menu_id`は、サーバーが今回入力したメニューバージョンと照合する。存在しないID、有効期間外、売り切れの商品は破棄する。オプション名も対象商品に登録済みのものだけを残す。

## 確定記録

共有注文へ追加する時点で、`order_items`へ次を保存する。

- `menu_item_id`
- `menu_version_snapshot`
- `menu_name_snapshot`
- `unit_price_snapshot`
- 数量と選択オプションのスナップショット
- 入力者、入力言語、入力日時、音声認識原文
- `llm_candidates_json`
- `selected_candidate_json`

メニュー更新後も既存注文明細の名称と価格は再計算しない。

## 障害時

外部モデルは設定したタイムアウトと再試行回数に従う。通常モデル、予備モデル、ローカル解析の順で切り替える。候補を作れない場合は技術的な例外を画面へ出さず、次を表示する。

```text
音声から候補を作れませんでした。メニューから選んでください
```

その場合もメニューボタン、商品名検索、数量ボタン、文字入力を利用できる。

## 交換可能な設定

AI接続は`app/services/ai_order.py`の`AiOrderAdapter`へ分離する。事業者、モデル、エンドポイント、プロンプト、構造化出力クラス、タイムアウト、再試行、店舗別月間上限を注文処理から独立して変更できる。
